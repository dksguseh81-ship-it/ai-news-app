# 뉴스 수집기 기능 개발 워크플로

아래 단계를 **순서대로** 실행한다. 브랜치 이름 인자: `$ARGUMENTS`

## 1단계: 현재 상태 확인

1. `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인한다.
2. 현재 브랜치가 `main`이 아니면:
   - 현재 브랜치 이름을 보여주며 **경고**한다. (예: "⚠️ 현재 `xxx` 브랜치입니다. main이 아닙니다.")
   - 커밋되지 않은 변경 사항이 있으면 함께 알린다.
   - 사용자에게 main으로 이동할지 물어보고, **답을 받을 때까지 다음 단계로 진행하지 않는다.**
   - 승인하면 `git checkout main`으로 이동한다. 변경 사항 때문에 이동이 실패하면 임의로 stash/reset 하지 말고 사용자에게 알린다.
   - 거절하면 워크플로를 중단한다.

## 2단계: 새 브랜치 생성

- `$ARGUMENTS`가 비어 있지 않으면 그 값을 브랜치 이름으로 사용한다.
- 비어 있으면:
  1. 어떤 기능을 개발할 것인지 사용자에게 묻는다.
  2. 답변을 바탕으로 **영어 소문자-하이픈 형식**(예: `add-bookmark-feature`)의 브랜치 이름을 제안한다.
  3. 사용자가 확인하거나 수정한 이름으로 진행한다.
- 이미 같은 이름의 브랜치가 있으면 알리고 다른 이름을 받는다.
- `git checkout -b <브랜치-이름>`으로 생성하고 이동한다.

## 3단계: 개발 시작 안내

브랜치 생성이 끝나면 다음 문구를 안내한다.

> 이제 개발을 시작하세요!

## 4단계: 프로젝트 기술 스택과 컨벤션 안내

프로젝트 루트의 `CLAUDE.md`를 읽고 다음을 요약해서 다시 알려 준다.

- 기술 스택 (Next.js, React, TypeScript, Tailwind CSS, Clerk, Neon + Drizzle, Claude API, Notion MCP 등 CLAUDE.md에 적힌 내용)
- 디렉터리/별칭 규칙 (`src/` 레이아웃, `@/*` → `src/*`)
- 참고 문서 (`PRD.md`, `ui.md`, `AGENTS.md`)와 Next.js 16 주의 사항
- 주요 명령어 (`npm run dev`, `npm run build`, `npm run lint`)
- 비밀 키는 서버 측 환경 변수에만 둔다는 규칙 등 CLAUDE.md의 컨벤션

CLAUDE.md의 최신 내용을 기준으로 하며, 기억에 의존하지 않는다.

## 5단계: 개발 진행

사용자가 요청하는 개발 작업을 평소처럼 도와준다.
사용자가 **`완료`** 또는 **`done`** 이라고 입력하면 6단계로 넘어간다.

## 6단계: 커밋 및 main 병합

1. `git status`와 `git diff --stat`으로 **변경된 파일 목록**을 보여준다. (추가/수정/삭제 구분, 추적되지 않는 파일 포함)
2. 변경 내용과 `git log`의 기존 메시지 스타일(한국어)을 참고해 **커밋 메시지를 자동으로 제안**한다.
3. 사용자에게 커밋 대상 파일과 메시지를 확인받는다. 수정 요청이 있으면 반영한다.
   - `.env*` 등 비밀 정보가 포함된 파일이 있으면 경고하고 제외한다.
4. 사용자가 **확인하면** 커밋한다. (`git add`는 확인된 파일만 지정, 시스템 메시지에 attribution 규칙이 있으면 따른다.)
5. `git checkout main`으로 이동한 뒤 `git merge <브랜치-이름>`으로 병합한다.
   - 충돌이 발생하면 임의로 해결하지 말고 충돌 파일을 보여주며 사용자와 상의한다.
6. 병합 후 작업 브랜치를 삭제할지 묻는다. 푸시는 사용자가 요청할 때만 한다.

## 7단계: 작업 요약

병합이 끝나면 다음을 요약해서 보여준다.

- 브랜치 이름과 병합 결과
- 커밋 메시지와 해시
- 변경된 파일 목록 및 주요 변경 내용
- 다음에 할 일 (예: 푸시, 후속 기능)
